# Contributing

Start with a failing synthetic case and state the invariant: exact versions, dependency tracking, withdrawal, restore trust, availability, coverage or budget. Keep missing evidence distinct from an unavailable dependency. Never replace a failed dependency check with a successful empty result.

Useful contributions include synthetic temporal or multilingual counterexamples, independent installation reports, storage adapters that preserve exact refs and embedding-space identities, clearer recovery guidance, and bounded performance improvements with an unchanged semantic oracle.

Run the installed-artifact suite described in `docs/TESTING.md`. Document before/after behavior, resource cost, assumptions and limits. Changes to pinned authority/retrieval bytes need an explicit compatibility review. Do not weaken tests or change expected answers merely to improve a benchmark score.

Do not submit private memories, conversations, credentials, model account tokens, production logs, host topology, database backups or personal embeddings. Use minimal generated fixtures. A contribution must identify its license and provenance. This project's MIT license applies to its original code; third-party assets require their own compatible permissions.

The current alpha reserves a separate policy-evidence module for future evaluated/admitted/rollback decisions. No learning algorithm may change user permissions, bypass authority revalidation or silently promote an experimental policy.
